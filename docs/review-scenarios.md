# 粗略代码审阅的状态推演

这些是手工审阅输入和预期状态，不是已经跑过的测试，也不生成 mock 性能数据。

| 场景 | 输入/事件 | 应在代码中看到的行为 |
|---|---|---|
| 可驱逐命中计费 | 空闲页包含一个 ref=0 命中页，另需两新页 | 上游需求计 3；活跃 ref>0 命中不额外占空闲容量 |
| 连续分配 | free=3，两个候选各需 2 | 第一个成功后第二个用 free=1 重新判断而拒绝 |
| 驱逐导致旧命中失效 | A 分配复用 B 的原缓存页 | B 在 A 成功后重新查 key，不缓存旧块 ID |
| 普通容量拒绝 | 队首需求大于 free-watermark | 页引用/空闲链/队列/绕行计数不变，仅增加诊断和扫描游标 |
| 固定窗口 | 队首后有 9 项，W=8，其中多项成功/跳过 | 最多检查原前 8 项，不将第 9 项补入 |
| 非队首前驱屏障 | A(2)、B(7)、C(0)、D(0)，A/B 拒绝而 C 成功 | A=3、B=8，此后 D 不得越过 B |
| 屏障自身准入 | 下一轮 A 未到 8、B 自身为 8且能放下 | B 可以准入；限制的是 B 后面的请求 |
| 抢占与最终清理 | B 带计数 8 进入运行、后被抢占、再取消 | 抢占仍为 8；最终取消才删除记录 |
| 非 KV 队首阻塞 | 无 token/seq 名额、外部依赖或不支持配置 | 不以 KV 窗口绕过；保留上游控制流 |
| 分块限制 | 关闭 chunking，后方某候选超当步 token 预算 | 候选消耗位置并留队；普通队首仍按原路径停止 |
| 短输入长输出 | 512 输入、4096 输出 | 只按当前已知 tokens 准入；未来增页和抢占仍原路径 |
| 漏发 | 10 s 计划 50 ID，只发 49，40 个达标 | 诊断 goodput=4.0、计划达标率80%，发生器门槛失败 |
| 缺首 token | 长输入 2250 中 30 个没有首 token | 记录 1.33% 缺失及条件 P99，全体 P99 留空 |
| 中途异常 | 分配器抛异常或 SSE 中途截断 | 分配异常传播；流式不完整计失败，不制造成功结果 |

当前只按用户要求进行文本层面的粗略审阅；以上状态断言尚未通过执行验证。
